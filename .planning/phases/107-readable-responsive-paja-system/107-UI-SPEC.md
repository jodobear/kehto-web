# Phase 107 — UI Design Contract

> Visual and interaction contract for Readable Responsive Paja System. Generated by gsd-ui-researcher; must pass gsd-ui-checker before implementation begins.

## Scope and Sources

This phase closes `VIS-01` through `VIS-03` and `PAJA-01` through `PAJA-04`. It changes presentation and local host interaction only. It MUST NOT add, remove, reshape, or reinterpret NAP messages, capabilities, routing, lifecycle behavior, security boundaries, or package versions.

Contract sources:

- `.planning/REQUIREMENTS.md`: semantic visual system, 12px routine-text floor, 375x812 non-clipping, Paja context and recovery requirements.
- `.planning/ROADMAP.md`: desktop split, phone-specific composition, existing-loader retry, protocol-no-drift success criteria.
- `.planning/milestones/v1.29-phases/105-published-convention-adoption-and-host-flows/105-UI-REVIEW.md`: authoritative `12/24` debt baseline.
- Live source: `packages/paja/src/host-page.ts`, `browser-host.ts`, `browser-runtime-tabs.ts`, `browser-target-frame.ts`, the feed/profile HTML, and `apps/playground/src/theme.ts`.

Phase 108 owns feed/profile recovery actions and copy. Phase 107 changes their semantic token, type, and spacing consumption only. Playground topology redesign, framework adoption, and broad rebranding remain out of scope.

Feed/profile declare the same `--ui-*` names once as aliases to the existing `--nap-theme-*` variables. Component selectors consume only `--ui-*`; raw color literals are allowed only in the declaration block.

## Spacing Scale

Declared compact scale; no additional spacing values:

| Token | Value | Usage |
|-------|-------|-------|
| `--ui-space-xs` | 4px | Inline icon/text gap, compact internal separation |
| `--ui-space-sm` | 8px | Control groups, compact padding |
| `--ui-space-md` | 16px | Default component padding and section gap |
| `--ui-space-lg` | 24px | Major panel padding and phone panel separation |
| `--ui-space-xl` | 32px | Desktop section separation |
| `--ui-space-2xl` | 48px | Phone control height and major layout break |
| `--ui-space-3xl` | 64px | Page-level separation only |

Exceptions: none. One-pixel borders and two-pixel focus indicators are strokes, not spacing. Desktop controls use a 32px minimum target; all phone controls, including tab share/close actions, use a 48px minimum target. Component radii do not create spacing values.

No scoped rule may retain the current 2px, 3px, 5px, 6px, 7px, 9px, 10px, 12px, or 14px margin/padding/gap values. Replace them with the declared scale.

## Typography

Exactly four sizes and two weights are permitted across the scoped surfaces.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / compact UI (`--ui-type-label`) | 12px | 400 | 1.5 |
| Body (`--ui-type-body`) | 14px | 400 | 1.5 |
| Heading (`--ui-type-heading`) | 18px | 600 | 1.25 |
| Display / product title (`--ui-type-display`) | 24px | 600 | 1.2 |

Allowed weights: regular `400` and semibold `600` only. Paja logs, target identifiers, feed timestamps, author names, profile public keys, status text, labels, and details all compute to at least 12px. No smaller metadata token is declared for this phase.

Use body text for explanations and recovery guidance; compact UI only for controls, status, logs, and secondary metadata. Use heading for error/empty-state headings. Display is reserved for product-level identity where space permits and must fall back to heading size in the compact Paja header without introducing another size.

## Color

### Distribution

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#101211` | Host canvas, stage matte, page background |
| Secondary (30%) | `#181b19` | Header, console, footer, dialogs, error card; raised controls use the single declared raised-surface token |
| Accent (10%) | `#d8c36a` | Product wordmark, active tab indicator, primary recovery CTA, selected-control indicator, visible focus ring |
| Destructive | not used | Phase 107 has no destructive action; error state uses semantic danger, not a destructive-action color |

Accent reserved for: `@kehto/paja` wordmark emphasis, active runtime tab border/indicator, `Retry target` primary action, selected signer/simulation control, and `:focus-visible` indicator. Accent MUST NOT color all buttons, body links, every heading, full panels, logs, or routine status text.

### Semantic states

| State | Foreground | Surface | Contract |
|-------|------------|---------|----------|
| Neutral | `--ui-color-foreground` / `--ui-color-muted` | background/surface/raised-surface roles | Default content hierarchy |
| Success | `#a9d38f` | normal surface | Ready/resolved text plus explicit state word; never color alone |
| Danger/error | `#f0a0a0` | `#2b1e1e` | Failure heading/icon/border plus plain-language text; never color alone |
| Disabled | muted foreground | raised surface | Native `disabled` plus reduced emphasis; preserve readable contrast |
| Focus | `#d8c36a` | transparent | Two-pixel visible outline with four-pixel offset; never remove browser focus without replacement |

Default Paja text/accent pairs exceed normal-text contrast targets on the dominant and secondary surfaces; `--ui-color-border` is strong enough to distinguish adjacent host surfaces. Host-provided feed/profile themes must preserve those same semantic distinctions rather than adding new accent roles.

## Visual Hierarchy

### Desktop — 1280×720

1. Primary focal point: active runtime stage.
2. Secondary: current target and active runtime-tab strip in the header.
3. Tertiary: development console and compact environment footer.

Preserve the working two-column composition: 360px console plus `minmax(0, 1fr)` stage. Header is 48px high; footer is at least 32px and may wrap rather than clip. Console and message log scroll independently. Stage never inherits console scrolling.

### Phone — 375×812

Use a phone composition at `max-width: 640px`; do not merely reorder the desktop grid.

1. Identity strip comes first: full `@kehto/paja` identity and current target remain visible. Target wraps to two lines before ellipsis; full value remains in its accessible name and `title`.
2. Runtime-tab strip occupies its own row, scrolls horizontally, and auto-reveals the active tab. Page-level horizontal scrolling is forbidden.
3. Essential command row shows lifecycle text, Theme, and Reload target. Controls are 48px high.
4. Main uses a 224px independently scrollable controls panel followed by the active stage. Pointer form stays first in the controls panel. The active stage receives at least 320px height in the 375×812 first viewport.
5. Footer becomes a two-column auto-row grid. Mode, HMR, runtime, simulation, and state wrap with `overflow-wrap: anywhere`; none are cut by a fixed footer height.

At 375×812, header, controls panel, stage, and footer must remain inside the viewport. Vertical scrolling within console, logs, tabs, and target content is allowed; hidden overflow that makes a host control or footer value unreachable is not.

### Error focal point

When target loading fails, stage focal point changes from iframe to the host error card:

1. `Target couldn't load` heading and short cause.
2. Accent primary `Retry target` action.
3. Secondary return action.
4. Collapsed technical details.

Do not show raw `<pre>` content as the primary stage.

## Target Recovery Interaction

The error surface MUST be host DOM adjacent to/replacing the active frame presentation, not error HTML inside the sandboxed iframe. This keeps event handlers inside Paja, avoids a new `postMessage` vocabulary, and leaves the NAP/session boundary unchanged.

| From | User/system event | UI result | Focus/result contract |
|------|-------------------|-----------|-----------------------|
| Empty | Submit non-empty pointer | Loading target… | Submit stays disabled only while current attempt runs |
| Loading | Existing loader succeeds and handshake completes | Target ready; show iframe | Focus may enter the active iframe only after user-initiated load/retry; do not move focus on background restore |
| Loading | Existing loader rejects | Error card; escaped detail collapsed | Announce the user-facing error once; do not force focus |
| Error | Activate Retry target with Enter, Space, pointer, or touch | Retrying target…; button disabled; panel `aria-busy="true"` | Call the existing single-frame `state.reload()` or existing active-tab reload path; never create a second concurrent attempt |
| Retrying | Retry fails | Same error card with updated escaped diagnostic | Re-enable Retry target; retain focus on it; announce changed failure once |
| Retrying | Retry succeeds | Active frame replaces error card; Target ready | Focus the active iframe element so keyboard users do not lose position when the retry button disappears |
| Error | Activate return action | Error remains; console becomes visible | Runtime-pointer mode focuses pointer input. External-target mode focuses first enabled Paja console control. No reload occurs. |

Diagnostic text is rendered with `textContent` or existing HTML escaping, wraps anywhere, and scrolls vertically inside its details region. Never interpolate an error string into executable markup.

## Responsive and Accessibility Contracts

- No routine text below 12px computed size. Text remains readable at 200% browser zoom without two-dimensional page scrolling.
- Every interactive control is reachable in logical DOM order, operable with keyboard, and has a visible two-pixel focus indicator unobscured by sticky rows or overflow containers.
- Dynamic lifecycle updates use one polite atomic status region. The error sentence may use `role="alert"`; its controls are outside the alert node. Do not announce unchanged status strings repeatedly.
- Loading/retrying state uses visible text and `aria-busy`; success/error use text plus semantic color. Spinner-only and color-only status are forbidden.
- Native button disabled state prevents duplicate retry. No positive-tabindex or custom keyboard emulation for new actions.
- Motion is unnecessary. Do not add loading/recovery animation; therefore reduced-motion has no special branch.
- At 375px width, `document.documentElement.scrollWidth` must equal `clientWidth`. Internal tab/log/console scrolling must not create page overflow.
- At 1280×720 and 375×812, no Paja host control, focus ring, target context, console content, or footer status is permanently clipped.

Standards basis: [WCAG 2.2 reflow, focus, target-size, and status-message criteria](https://www.w3.org/TR/WCAG22/) and [W3C `role=status` technique](https://www.w3.org/WAI/WCAG21/Techniques/aria/ARIA22).

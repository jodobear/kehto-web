## Trust Boundaries

| Boundary | Description |
|---|---|
| Paja configuration → replica controller | Ordered server URLs and policy values become outbound authority. |
| signer lifecycle → active replica operation | An identity change can arrive while authorization or I/O is pending. |
| host confirmation UI → Paja operation | Consent controls durable public egress and must describe its full scope. |
| Paja diagnostics → sandboxed napplet | Host-only per-replica evidence must not become a new wire API. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan | Verification | Residual risk |
|---|---|---|---|---|---|---|---|
| T-103-01 | Information disclosure | replica egress | high | mitigate | Configured-only target set, pre-egress policy, tuple consent, and no discovery fallback constrain where a napplet can cause bytes to go. | Ordered-attempt and pre-egress tests. | User-approved public uploads remain durable by design. |
| T-103-05 | Spoofing | per-server authorization | high | mitigate | Sign separately per attempt with captured identity and server scope; abort on identity mismatch/change. | Signer-switch and server-tag regressions. | A successful remote server controls its own storage retention. |

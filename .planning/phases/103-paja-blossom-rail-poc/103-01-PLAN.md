<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| sandboxed napplet → runtime | Untrusted bytes and metadata request a host-owned upload. |
| Paja browser host → local verifier route | Host sends an untrusted remote descriptor URL for policy-controlled proof. |
| Paja verifier → Blossom/CDN | Untrusted descriptor URL, redirects, DNS answers, response bytes, and MIME claims cross into the host. |
| upload runtime → resource service | A verified result becomes an exact, window-scoped preview capability. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan | Verification | Residual risk |
|---|---|---|---|---|---|---|---|
| T-103-01 | Information disclosure | upload request path | high | mitigate | ACL remains upstream of Paja; host verifier and grant callback are unavailable to the iframe; later tuple consent is added in Plan 03. | Browser tracer proves standard envelopes only; Plan 04 adds full authority checks. | User-approved bytes may become durable public copies. |
| T-103-02 | Tampering | descriptor and stored GET | high | mitigate | Require descriptor structure, full GET, exact digest/size, and sniffed MIME before result or grant. | Altered-byte and malformed-claim tests. | A correctly verified public object can change after retrieval; preview uses the retained verified bytes. |
| T-103-03 | Elevation of privilege | verifier outbound fetch | high | mitigate | Enforce HTTPS, DNS-time address checks, pinned connection, redirect revalidation, and byte cap in Paja server code. | Verifier policy tests cover private address and redirect rejection. | Public HTTPS targets remain intentionally reachable for verified upload results. |
| T-103-04 | Information disclosure | exact resource grant | high | mitigate | Bind preverified bytes to exact URL, window, and identity; erase grants before teardown returns. | Multi-window and late-response tests. | A live owning window can read only its granted verified bytes. |
| T-103-SC | Tampering | package manager | low | accept | No package-manager install is authorized; implementation uses Node and workspace facilities already present. | `git diff --name-only` contains no lockfile or dependency manifest change. | Existing dependency supply-chain posture remains unchanged. |
</threat_model>
